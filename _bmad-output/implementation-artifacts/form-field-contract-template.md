# 表单字段契约模板

用于后续所有新增/编辑页的 Story / Dev Notes，避免因为字段默认值、空值策略或组件语义不清导致实现偏差。

---

## 使用方式

对每一个“复杂字段”至少补齐下面 4 项：

1. 组件类型  
2. 前端默认值  
3. 提交值类型  
4. 空值策略

推荐额外补齐：

5. 回填映射规则  
6. 编辑态是否只读  
7. 最小测试点

## 示例 1：`restricted_countries`

- 业务含义：禁止经营国家/地区，可为空
- 组件类型：`Select` tags / 可输入多值
- 前端默认值：`[]`
- 提交值类型：`string[]`
- 空值策略：无值时提交 `[]`，不要传 `undefined`
- 回填映射规则：后端无值时映射为 `[]`
- 编辑态规则：可编辑
- 测试重点：空值提交不报错；多值能正确映射到 payload

## 示例 2：`invoice_infos`

- 业务含义：开票信息子表，至少一条
- 组件类型：`Form.List` + 行内输入
- 前端默认值：至少一条空行
- 提交值类型：对象数组
- 空值策略：数组本身不能是 `undefined`；子项字段由表单校验约束
- 回填映射规则：详情接口返回数组后逐行映射；无值时补一条空行
- 编辑态规则：可编辑，可新增删除行
- 测试重点：新增行、删除行、失焦后值不丢失、payload 顺序正确

## 示例 3：`supplier_name`

- 业务含义：供应商名称
- 组件类型：若无主数据搜索接口，使用普通 `Input`；只有在存在真实候选接口时才使用远程搜索 `Select`
- 前端默认值：`''`
- 提交值类型：`string`
- 空值策略：无值时为 `''`，由必填校验阻止提交
- 回填映射规则：详情接口返回字符串，直接回填
- 编辑态规则：当业务规则允许时可编辑
- 测试重点：输入后可稳定保留；提交前会 `trim()`；无接口时不要伪装成远程搜索

## 建议落地规则

- 不要让“组件语义”和“真实数据来源”不一致  
  例：没有远程接口时，不要伪装成“远程搜索 Select”

- 所有表单页尽量统一提供两个函数：
  - `toFormValues()`
  - `toPayload()`

- 所有可选数组字段都不要假设一定有值
  - `undefined` 先转成 `[]`

- 所有子表字段优先使用 `Form.List`
  - 不要用容易触发整行重绘导致值丢失的临时拼装方式

- Story 中凡是“多选 / tags / 子表 / 数字可空 / 编辑态只读”的字段，都建议写清契约
