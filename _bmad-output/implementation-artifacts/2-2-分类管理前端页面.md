# Story 2.2: 分类管理前端页面

**Status:** review
**Story Key:** 2-2-分类管理前端页面
**Epic:** 2 - 产品分类管理
**Date:** 2026-04-16

---

## User Story

As a 产品部用户,
I want 在分类管理页面通过树形结构直观地浏览、新增、编辑和排序分类,
So that 我可以高效地维护产品分类体系。

---

## Acceptance Criteria

**Given** 用户进入分类管理页面  
**When** 页面加载完成  
**Then** 左侧显示分类树形结构，支持展开/折叠各级节点  
**And** 右侧显示选中分类的详情/编辑区域

**Given** 用户在分类树上点击“新增子分类”  
**When** 填写分类编码和名称并保存  
**Then** 新分类出现在树的对应位置  
**And** 保存成功后顶部 `message` 提示“保存成功”

**Given** 用户拖拽同级分类调整排序  
**When** 拖拽完成释放  
**Then** 排序更新并即时反映在分类树中

**Given** 用户尝试删除一个已有 SPU 关联的分类  
**When** 点击删除按钮  
**Then** 弹出确认对话框，确认后显示错误提示“该分类下已有产品关联，无法删除”

**Given** 商务部/财务部用户进入分类管理页面  
**When** 页面加载完成  
**Then** 可以浏览分类树，但新增/编辑/删除/排序按钮不显示或禁用

## Dev Notes

### 现有代码基础

  - `erp-frontend/src/components/layout/SideMenu.tsx`
- API client 已统一封装在 `erp-frontend/src/api/client.ts`
- 角色权限读取已可通过 `erp-frontend/src/hooks/usePermission.ts` 获取

### 推荐新增/修改文件

- `erp-frontend/src/api/categories.ts`
- `erp-frontend/src/features/products/categories/pages/CategoryPage.tsx`
- `erp-frontend/src/features/products/categories/components/*`（如确有必要可拆）
- `erp-frontend/src/test/features/CategoryPage.test.tsx` 或 `src/test/pages/CategoryPage.test.tsx`

### 页面结构建议

1. 页面整体保持在现有 `AppLayout` 内容区内，不改布局骨架
2. 顶部可使用 `SectionTitle` 标题“分类管理”
3. 主体双栏：
   - 左栏：分类树卡片
   - 右栏：分类详情 / 编辑表单卡片
4. 表单区底部建议用 `FixedActionBar` 或等价固定操作栏
5. 不要把页面做成弹窗编辑，PRD 明确更偏向主工作区内操作

### 交互与组件约束

- 复用已有通用组件：
  - `FilterCard`：可用于承载树工具栏或操作区，不强制作为筛选区
  - `SectionTitle`：右侧分区标题
  - `FixedActionBar`：右侧编辑表单保存/取消
- UX 文档明确推荐：
  - 分类选择 / 层级交互可使用树形结构
  - 成功反馈使用顶部 `message`
  - 删除确认使用 `Popconfirm`
- 若 Ant Design 原生 `Tree` / `Tree.DirectoryTree` 更适合，不要为了“看起来高级”硬上复杂自定义组件

### 排序实现建议

- AC 写的是“拖拽同级分类调整排序”
- 优先确认团队当前依赖里是否已有合适拖拽方案；若无新增依赖会显著增加复杂度，则可在实现时采用更轻量但清晰的同级排序交互
- 无论交互形式如何，必须满足：
  - 只能调整同级顺序
  - 排序结果即时反映在树结构中
  - 最终调用 `PATCH /api/v1/products/categories/{id}/sort`

### 权限边界

- 产品部 / 管理员：可写
- 商务部 / 财务部：只读
- 前端权限来源优先复用 `usePermission().canCreateProduct`
- 只读态不要只靠隐藏按钮，右侧编辑表单也要禁用或切换为只读展示

### API 对接约定

- 后端分类接口已在 2.1 提供：
  - `GET /api/v1/products/categories/tree`
  - `POST /api/v1/products/categories`
  - `PATCH /api/v1/products/categories/{id}`
  - `PATCH /api/v1/products/categories/{id}/sort`
  - `DELETE /api/v1/products/categories/{id}`
- 删除失败时需要正确展示后端中文错误消息：
  - `该分类下已有产品关联，无法删除`
  - `该分类下存在子分类，无法删除`

### 测试重点

- 页面首次加载能拉取并渲染分类树
- 点击树节点后右侧详情/编辑区更新
- 产品部用户可见新增/编辑/删除操作
- 商务部/财务部用户仅可浏览，不可操作
- 保存调用正确 API，并在成功后提示“保存成功”
- 删除失败时展示后端返回的中文错误提示

### 风险提醒

- `2-2` 直接依赖 `2-1` 接口形状，开发时不要擅自改后端响应结构
- 若排序交互需要新依赖，需先确认是否值得引入；默认优先不新增依赖
- 当前 `CategoryPage` 已在路由中 KeepAlive，页面状态设计需考虑切页签返回后的体验
