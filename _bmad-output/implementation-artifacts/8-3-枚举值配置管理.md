# Story 8.3: 枚举值配置管理

**Status:** review
**Story Key:** 8-3-枚举值配置管理
**Epic:** 8 - 数据导入与系统配置
**Date:** 2026-04-23

---

## User Story

As a 管理员,
I want 维护系统全局枚举值（单位、产品类型、证书类型、资料类型、国家/地区等）,
So that 各子模块的下拉选项可以灵活调整，不需要修改代码。

---

## Acceptance Criteria

**Given** `enums` 表已创建（含 `enum_group`、`enum_key`、`enum_value`、`sort_order` 等核心字段）  
**When** 管理员调用 `GET /api/v1/enums?group=unit`  
**Then** 返回“单位”枚举组的可用值列表，供后续模块稳定复用

**Given** 管理员新增枚举值  
**When** 调用 `POST /api/v1/enums`  
**Then** 新枚举值创建成功，并可立即在对应枚举组查询结果中返回

**Given** 管理员编辑枚举值、调整排序或切换启停用  
**When** 调用枚举更新接口  
**Then** 对应枚举组列表立即反映变化

**Given** 国家/地区枚举纳入系统级枚举管理  
**When** 查询 `country_region` 枚举组  
**Then** 返回标准编码（如 `CN`、`US`、`GLOBAL`）及展示文案  
**And** `GLOBAL` 默认存在且不可删除

**Given** 管理员进入枚举配置页面  
**When** 页面加载完成  
**Then** 左侧展示系统枚举组列表（单位、产品类型、产品状态、包装类型、电参数、证书类型、FAQ问题类型、资料类型、币种、国家/地区）  
**And** 右侧展示所选枚举组的枚举值列表  
**And** 支持新增、编辑、排序、启停用以及受约束的删除  
**And** 非管理员不可访问或明确提示无权限

## Dev Notes

### 现有模式与架构约束

- Architecture 已明确：枚举管理后端对应 `app/*/enums.*`，前端对应 `features/admin/enums/`
- 前端页面应保持紧凑内容区，不额外展示页面标题；优先保留筛选/操作/表格主内容
- KeepAlive 页面仍由路由层挂载，页面自身不要依赖 `useParams()` 决定核心模式
- 枚举管理属于管理员专属能力，前端菜单可见性与后端写接口都应收敛到管理员权限

### 关键实现约束

1. 本 Story 只做系统全局枚举值配置管理，不顺手改造 8.1 / 8.2 或其他 Epic 业务页
2. `country_region` 必须作为系统级枚举组提供，国家/地区字段以标准编码为稳定契约
3. `GLOBAL` 默认存在、不可删除；若允许停用，也应显式禁止，避免破坏系统默认区域语义
4. 读接口需为后续各业务模块复用预留稳定命名；写接口仅管理员开放
5. 枚举组清单优先覆盖：`unit`、`product_type`、`product_status`、`package_type`、`electrical_params`、`certificate_type`、`faq_question_type`、`document_type`、`currency`、`country_region`
6. 列表展示至少包含：编码、显示值、排序、状态、内置标记、更新时间
7. 新增/编辑表单需明确字段契约：
   - `enum_group`：提交值类型 `string`，新增时必填，编辑时默认锁定当前组
   - `enum_key`：提交值类型 `string`，默认转大写用于编码型枚举，空值不允许
   - `enum_value`：提交值类型 `string`，显示文案，空值不允许
   - `sort_order`：提交值类型 `number`，默认 `0`
   - `is_enabled`：提交值类型 `boolean`，默认 `true`
8. 可为后续表单复用预留 `GET /api/v1/enums/groups` 与 `GET /api/v1/enums` 的稳定返回结构，但不要在本 Story 中全面替换现有表单常量
