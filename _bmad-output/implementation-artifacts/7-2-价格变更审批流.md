# Story 7.2: 价格变更审批流

**Status:** review
**Story Key:** 7-2-价格变更审批流
**Epic:** 7 - 销售价格管理与审批
**Date:** 2026-04-21

---

## User Story

As a 财务部用户,
I want 提交价格变更后需经审批，审批通过前原有价格继续生效,
So that 价格变更有控制、有记录，不会未经审批就影响业务报价。

---

## Acceptance Criteria

**Given** 财务部用户提交价格变更  
**When** 调用 `POST /api/v1/prices/{id}/submit`  
**Then** 价格记录状态变为"待审批"（FR26）  
**And** 审计日志记录提交操作（NFR8）

**Given** 价格处于"待审批"状态  
**When** SKU 详情页查看价格  
**Then** 展示的仍是上一次已审批通过的价格（FR26）

**Given** 具有 `product:price:approve` 权限的用户  
**When** 调用 `POST /api/v1/prices/{id}/approve`  
**Then** 价格状态变为"已生效"，新价格在 SKU 详情页展示（FR27）  
**And** 审计日志记录审批操作（包含审批人、时间、价格变更前后值）

**Given** 审批人驳回价格变更  
**When** 调用 `POST /api/v1/prices/{id}/reject` 并填写驳回原因  
**Then** 价格状态变为"已驳回"（FR27）  
**And** 财务人员可编辑后重新提交

---

## Scope

### In Scope

- 价格审批状态机与审批相关数据字段、迁移与 5-file backend 结构扩展
- `POST /api/v1/prices/{id}/submit`、`POST /api/v1/prices/{id}/approve`、`POST /api/v1/prices/{id}/reject`
- 价格草稿版本与已生效版本并存的数据模型，确保“审批通过前原价格继续生效”
- 审批角色控制、提交/审批/驳回的状态流转校验
- 审计日志记录提交、审批、驳回操作
- 按 SKU 读取当前已生效价格的只读接口，为后续 SKU 详情页聚合复用
- 最小可用后端测试：状态流转、旧价继续生效、驳回后重提、权限、审计日志

### Out of Scope

- 价格管理前端页面、审批按钮、状态标签 UI → Story 7.3
- SKU 详情页真实前端聚合展示改造
- 多级审批链、审批备注流转历史页面、审批通知
- 审批权限中心化配置系统；本 Story 沿用现有角色/依赖注入模式做最小实现

### 关键实现约束

1. 本 Story 只做审批流后端与生效价格读取底座，不提前实现 7.3 前端页面
2. 必须满足“审批通过前原有价格继续生效”，不能只给现有价格行加状态后直接覆盖生效数据
3. 需要明确区分“当前草稿/待审批价格”和“当前已生效价格”两套视图
4. 审批动作必须记录审计日志，且包含变更前后价格内容
5. 审批权限沿用当前角色依赖注入模式；如果 `product:price:approve` 需要用角色代替，必须在故事记录中写明假设
6. 不引入工作流引擎或新依赖；现有 FastAPI / SQLAlchemy / Pydantic / pytest 足够完成本 Story

### 推荐接口范围

- `POST /api/v1/prices/{id}/submit`
- `POST /api/v1/prices/{id}/approve`
- `POST /api/v1/prices/{id}/reject`
- `GET /api/v1/prices/sku/{sku_id}/effective`

### 推荐数据设计方向

- `prices`
  - `approval_status: draft | pending | active | rejected`
  - `submitted_at` / `submitted_by`
  - `approved_at` / `approved_by`
  - `rejected_at` / `rejected_by`
  - `rejection_reason`
- `price_regions`
  - 增加版本阶段字段，如 `version_stage: draft | approved`
  - 同一 `price_id + version_stage + country_code` 保持唯一

### 测试重点

- 新建价格后处于草稿或等价可提交状态
- 提交后状态变为待审批，并写入审计日志
- 待审批时 `GET /api/v1/prices/sku/{sku_id}/effective` 返回旧的已生效价格
- 审批通过后草稿价格替换已生效价格
- 驳回后记录原因，且财务可继续编辑再提交
- 未授权用户无法审批
