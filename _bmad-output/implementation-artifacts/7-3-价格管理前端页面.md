# Story 7.3: 价格管理前端页面

**Status:** review
**Story Key:** 7-3-价格管理前端页面
**Epic:** 7 - 销售价格管理与审批
**Date:** 2026-04-22

---

## User Story

As a 财务部用户,
I want 在价格管理页面高效设置和管理各 SKU 的区域价格，清晰了解审批进度,
So that 定价工作可以流畅地完成。

---

## Acceptance Criteria

**Given** 用户进入价格列表页  
**When** 页面加载完成  
**Then** 筛选区：一级分类、供应商、关键词（SKU编码/名称）  
**And** 表格列：SKU编码、SKU中文名称、供应商、采购价(CNY)、销售价摘要、审批状态、更新时间  
**And** 审批状态标签：待审批（蓝 #1677ff）、已生效（绿 #52c41a）、已驳回（红 #ff4d4f）（UX-DR15）

**Given** 用户新增价格  
**When** 选择 SKU 后  
**Then** 系统自动带出 SKU 信息（只读），下方为区域价格可编辑子表  
**And** 每行一个区域（国家/地区、销售价、列表价、币种、备注）  
**And** 支持新增行/删除行

**Given** 价格状态为"已驳回"  
**When** 财务人员查看该记录  
**Then** 可以编辑后重新提交

## Scope

### In Scope

- 价格列表页、价格新增页、价格编辑页

- 实现价格详情页双视图，清晰区分“当前审批稿”和“当前生效价格”
- 实现价格新增/编辑页，支持 SKU 搜索、SKU 只读信息自动带出、区域价格子表多行增删
- 对接 KeepAlive 路由、页签标题、查询缓存刷新与详情缓存同步

### Out of Scope

- 审批人视角的审批/驳回操作页
- SKU 详情页价格聚合展示改造
- 价格历史版本对比、审批流轨迹、通知提醒
- 新的后端接口、审批流规则或权限模型改造
- 7.4 或 Epic 8 相关内容

## Dev Notes

### 现有前端基础

- 当前价格模块仅有占位列表页：
  - `erp-frontend/src/features/prices/pages/PriceListPage.tsx`
- 现有模式优先参考：
  - `erp-frontend/src/features/products/skus/pages/SKUListPage.tsx`
  - `erp-frontend/src/features/products/skus/pages/SKUFormPage.tsx`
  - `erp-frontend/src/features/products/faqs/pages/FAQListPage.tsx`
  - `erp-frontend/src/features/products/documents/pages/DocumentFormPage.tsx`

### 关键实现约束

1. 7.3 只消费现有 7.1 / 7.2 后端接口，不改造审批流或 SKU 详情页价格聚合展示
2. 列表页保持当前仓库已收敛的紧凑内容区，不额外展示页面标题
3. 新增 / 编辑页必须遵循“三列表单 + 独立卡片分区 + 16px 卡片间距 + columnGap 24 / rowGap 16”
4. KeepAlive 页面不要依赖 `useParams()` 决定模式；路由层必须显式传 `mode` 与 `priceId`
5. 复杂字段必须明确契约：
   - `sku_id`：远程搜索 Select，前端默认值 `undefined`，提交值类型 `number`
   - `regions`：`Form.List`，前端默认值 `[]`，提交值类型 `PriceRegionPayload[]`，空值策略为提交前兜底 `[]`
   - SKU 快照字段：只读展示，不进入提交 payload
6. 已驳回记录允许编辑并重新提交；待审批记录不可编辑，前端需显式提示
7. 没有独立搜索接口时，SKU 搜索直接复用现有 `skus.list` 的 `keyword` 能力，不伪造本地假搜索
8. 建议统一实现 `toPriceFormValues()` / `toPricePayload()`，避免字段映射散落在页面逻辑中
