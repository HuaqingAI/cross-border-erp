## 一、业务背景

### 公司概况

本系统服务于一家专注跨境 TOB 业务的医疗器械出口企业。客户均为海外企业买家，产品全部为非标医疗器械，单品价值较高，对合规性（证书、资质）要求严格。

### 现有系统格局

| 系统 | 职责范围 | 使用方 |
|------|----------|--------|
| 外部 CRM | 线索 → 商机 → 成交 | 销售团队 |
| **本 ERP（待建）** | 销售订单 → 报关完结 | 运营、采购、仓储、物流 |
| 金蝶 | 财务记账 | 财务团队 |

### 为什么要建这套系统

原有系统基于钉钉宜搭搭建，随业务增长，平台能力的限制已无法满足业务需要，决定自研一套可完整覆盖履约链路的 ERP 系统，以 AI 辅助开发为主要建设方式。

## 三、核心业务规则

### 3.1 产品主数据结构

产品主数据采用两级结构，SPU 与供应商一对一绑定：

```
SPU（标准产品单元，绑定唯一供应商）
  │── 基础信息：三级分类、SPU编码、SPU名称、客户质保期、单位、禁止经营国家
  │── 采购信息：供应商（唯一）、厂家型号、采购质保期、供应商质保说明
  │── 开票信息（子表）：开票品名、开票单位、开票型号、公司主体（多主体）
  │── 挂载：证书、资料、FAQ
  │
  └── SKU（SPU 下的规格变体，供应商从 SPU 继承）
        ├── 基础信息：SKU编码（公司自有规则）、中文名称、英文名称、产品型号
        ├── 产品属性：产品类型、核心参数、产品状态（上架/下架）、电参数、
        │            禁止经营国家、原理、用途、产品材质、单位、有无插头
        ├── 分类：一级/二级/三级分类（从 SPU 继承）
        ├── 特殊属性：是否特殊属性 + 说明
        ├── 包装信息：包装类型、包装数量
        ├── 包装明细（子表）：净重(KG)、毛重(KG)、长(CM)、宽(CM)、高(CM)、体积(CBM)
        ├── 报关信息：报关HSCODE、监管条件、申报要素、退税税点、是否已维护报关信息
        ├── 产品图片：文件上传
        └── 销售价格表（只读，从财务模块关联）：按国家/地区的销售价、列表价、币种
```

**关键规则：**
- SPU 与供应商一对一绑定，SKU 从 SPU 继承供应商，不需要单独绑定
- SKU 是 SPU 下的规格变体（如不同尺寸/配置）
- 每个 SKU 使用公司自有编码规则，全局唯一
- 库存以 SKU 为最小单位管理，不允许跨供应商合并库存
- 公司存在多个法律主体，不同产品可能用不同主体采购/开票

### 3.2 核心履约流程

**主线流程（订单驱动）：**
```
销售订单 → 发货需求（明细维度）→ 采购 → 仓储（质检入库）→ 物流发运 → 报关
```

**发货需求是流程枢纽：**
- 销售订单确认后，按明细行生成发货需求
- 发货需求以 SKU 明细为维度，是后续采购、仓储、发运的驱动源
- 一张销售订单的多个 SKU 生成多条发货需求
- 发货需求驱动采购：未有库存的需转采购单（按供应商拆分）
- 发货需求驱动出库：已有库存的可直接安排出库发运

### 3.3 两种采购模式

**模式一：订单驱动采购（主要模式）**
```
销售订单 → 发货需求 → 按供应商拆分采购单 → 供应商发货 → 质检入库 → 出库发运
```
- 备货极少，基本零库存运营
- 一张销售订单可包含多个 SKU、涉及多个供应商
- 发货需求按供应商维度拆分生成多张采购单
- 采购单与发货需求、销售订单存在明确关联关系

**模式二：自主备货采购**
```
采购部门主动发起 → 采购单 → 质检入库（工厂仓或自营仓）→ 后续匹配发货需求出库
```
- 备货不与特定订单绑定
- 入库后需支持与后续发货需求的库存匹配/分配

### 3.4 仓库类型

| 仓库类型 | 说明 | 货权归属 |
|----------|------|----------|
| 工厂仓 | 货物暂存于供应商工厂，尚未实际移库 | 已属公司 |
| 自营仓 | 公司自有或租赁仓库 | 公司 |

两种仓库均需在系统中管理库存状态，支持库存查询和出入库操作。

### 3.5 多币种与汇率

- 销售结算：外币（主要为 USD、EUR 等）
- 采购结算：人民币（CNY）
- 汇率维护：财务人员每月在系统中维护月度汇率表
- 系统需支持报表中的多币种换算

### 3.6 入库质检与整改

货物入仓前需经过清点、质检、整改流程，系统需记录该环节：

| 场景 | 执行人 | 说明 |
|------|--------|------|
| 货物发往自营仓 | 公司制造部 | 公司自有团队负责清点、质检、整改 |
| 货物存于工厂仓 | 工厂人员或公司人员 | 可由供应商代为执行，也可公司派人 |

系统需支持：
- 入库质检记录（质检结果、问题项）
- 整改跟踪（整改内容、完成状态）
- 质检通过后方可正式入库

---

### 3.7 证书与资质管理

- 证书归属支持三种模式：通用（全部产品）、SPU 归属、按分类归属
- 证书类型包括但不限于：CE 认证、FDA 注册、目标国医疗器械注册证
- 证书具有有效期（起始-结束），需支持到期预警
- 发运时，系统应能关联并输出对应的证书资料
- 详细字段定义见 3.1 产品管理子模块中的"产品证书管理"

## 四、核心功能模块

### 模块一：销售订单管理
- 手工录入销售订单（含客户信息、产品 SKU、数量、单价、币种）
- 订单状态跟踪（基于下游单据聚合计算）
- 后期：CRM 接口对接，自动创建销售订单

### 模块二：发货需求管理
- 由销售订单按明细行生成发货需求
- 以 SKU 为维度，是后续采购、仓储、发运的驱动源
- 发货需求状态跟踪（待采购、采购中、已入库、待发运、已发运）
- 支持查看库存匹配情况（有库存可直接出库 vs. 需新采购）
- 发货需求与销售订单的关联关系

### 模块三：采购管理
- 支持两种采购模式：由发货需求生成采购单、独立发起备货采购
- 发货需求按供应商维度拆分生成采购单
- 采购单管理（供应商、SKU、数量、价格、交期）
- 采购状态跟踪（待确认、已下单、在途、已到货）
- 采购单与发货需求、入库单关联

### 模块四：仓储管理
- 工厂仓与自营仓的库存管理
- 入库质检流程：清点 → 质检 → 整改（如需）→ 质检通过 → 正式入库
- 入库操作（关联采购单，需质检通过）
- 出库操作（关联发货需求/发运单）
- 库存查询与库存明细（以 SKU 为维度）
- 备货库存与发货需求的分配匹配

### 模块五：物流与发运管理
- 发运计划创建（关联发货需求、出库单）
- 支持拆单发运：一张销售订单可分多批次发运
- 发运单与发货需求、销售订单的关联关系
- 货代/物流商管理
- 运单信息录入（运单号、头程/尾程、预计到港）
- 发运状态跟踪

### 模块六：报关管理
- 报关资料归集（报关单、装箱单、发票等）
- 报关状态跟踪
- 清关资料输出给客户
- 报关完结确认

### 模块七：产品管理（含证书、资料、FAQ）
- 分类管理：三级分类树维护
- SPU 管理：基础信息、采购信息（供应商绑定）、开票信息（多主体）
- SKU 管理：规格变体、产品属性、包装信息、报关信息、产品图片
- 产品证书管理：归属模型（通用/SPU/分类）、有效期预警
- 产品资料库管理：归属模型（通用/指定SKU/分类）、国家/地区维度
- FAQ 管理：全局或 SPU 级别
- SKU 详情页聚合展示：证书 + 资料 + FAQ + 销售价格
- 详细字段定义见 3.1 产品管理子模块

### 模块八：回款管理
- 应收账款录入与跟踪
- 回款记录（收款日期、金额、币种）
- 订单回款状态（未收款、部分收款、已收款）
- 汇率换算支持

### 模块九：售后管理
